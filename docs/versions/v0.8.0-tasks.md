### **Task 1 POV-88: Containerization (Docker/Podman)**

**Title:** `feat(infra): containerize application using Jib`

**Description:**
Configure the project to build a container image using Jib (JVM mode). - `mvn clean package -Dquarkus.container-image.build=true` successfully builds a container image (OCI compliant).
- The container starts successfully and connects to a PostgreSQL database provided via env vars (verified on Docker or Podman).
- `RUNBOOK.md` is updated with instructions for running the container (Docker/Podman).

### **Task 3 POV-90: Standardize Entity Processing Logs**

**Title:** `feat(observability): standardize entity processing logs`

**Description:**
Implement a consistent structured logging format (Logfmt style) for key processing steps (Enrichment, Summarization, Briefing). Logs should follow the pattern: key="value" for all string values. Numeric metrics must be raw numbers with units in the key (e.g., duration_ms). Example: entityType="video" id="xyz123" topic="AI News" author="Some Channel" action="summarize" duration_ms=12300 status=success.
Refactor logging to reduce noise and redundancy (e.g., `GenAiPool` key acquisition, overlapping service logs).

**Acceptance Criteria:**
- Logs for a full orchestration run follow the structured Logfmt format including Topic and Author.
- Redundant logs are removed or demoted to DEBUG.
- No redundant/spammy logs.

- **Context:** `OrchestratorService.java`, `ContentCreationService.java`, `VideoSummaryService.java`, `GenAiPool.java`

### **Task 4 POV-91: Refactor Orchestration API & AJAX**

**Title:** `refactor(api): use request object for orchestration and standardize AJAX`

**Description:**
1.  **Backend:** Refactor `OrchestratorResource.runOrchestration` to accept a `OrchestrationRequest` JSON body instead of multiple query parameters.
2.  **Frontend:** Update `admin.js` to implement a truly generic `handleAjaxFormSubmit` that serializes form data into a JSON object for the request body. Update `admin.html` to use this new mechanism.

**Acceptance Criteria:**
- The `POST /api/v1/orchestrator/run` endpoint is refactored to accept a JSON request body containing orchestration parameters (`startDate`, `endDate`, `processPending`, etc.).
- The "Run Orchestration" form in the Admin UI successfully calls the refactored endpoint, sending form data as a JSON payload.
- The `handleAjaxFormSubmit` function in `admin.js` is generalized to serialize form data into a JSON body for any form it's attached to, removing the special handling for `orchestrationForm`.
