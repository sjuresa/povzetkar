# Version 0.13.0 Planning Process: Input Mastery & UX Foundation

**Status:** Draft
**Date:** March 19, 2026

## Introduction
This document details the iterative planning process for Version 0.13.0. The goal was to pivot from a purely infrastructure-focused "Production Hardening" phase to a user-centric "Professional Grade" frontend evolution, establishing the foundations for long-term scalability and user adoption.

## Phase 1: Strategic Evaluation & Feature Selection

During the initial review of the v2.7 Roadmap, we analyzed the current state of the MVP (v0.12). 

### Discussion 1: Pivot from "Production Hardening" to "UX Foundation"

*   **Initial Proposal:** Strictly follow the roadmap (Monitoring, DAST, Backups).

    *   **Pros:** Increases operational security and observability early.
    *   **Cons:** Users still interact with "MVP-style" placeholders (Loading text, missing Topic CRUD). The gap between backend maturity (v0.11) and frontend polish (v0.12) becomes too wide.

*   **Counter-Proposal:** Pivot v0.13 to "Input Mastery & UX Foundation".
    *   **Pros:** 
        *   Establishes "Professional Grade" UI patterns (Skeletons, Error Boundaries, i18n) that will be used for all future features.
        *   Completes the core loop for data ingestion (Topics and Source library).
        *   Provides immediate tangible value to the end user.
    *   **Cons:** Defers purely operational tasks (Prometheus/DAST) to a later version.

*   **Final Decision:** **Pivoted to UX/Input Mastery.** We concluded that a premium feel and reliable input management are more critical for the current development stage than advanced monitoring.

---

## Phase 2: Scoping and Performance Strategy

### Discussion 2: Splitting v0.13 into v0.13.0 and v0.14.0

*   **Initial Proposal:** Include all Input (Topics/Sources) and Output (Briefings/Reports) management in one version.
    *   **Arguments FOR:** Delivers a "complete" product cycle in one go.
    *   **Arguments AGAINST:** 
        *   Estimated effort approached 60 hours, increasing risk of regression and planning fatigue.

        *   Mixing input management with complex RAG/Briefing UI might dilute the focus on UX resilience.

*   **Final Decision:** **Split the scope.** 
    *   **v0.13.0 (Input Mastery):** Focus on Topics, Source Library, and global UX resilience.
    *   **v0.14.0 (Output Mastery):** Focus on Briefings, Custom Reports, and Admin controls.
    *   **Justification:** This allows us to perfect the "inward" data flow and the foundational UI components (Pagination, Forms, Toasts) before tackling the complex "outward" analytical views.

## Phase 3: Testing & Automation Philosophy

### Discussion 3: Integrated vs. Separate Test Automation

*   **Initial Proposal:** Create a separate task at the end of the version for "Test Automation".
    *   **Arguments FOR:** Allows the developer to focus purely on implementation first, then "harden" with tests.
    *   **Arguments AGAINST:** 
        *   Leads to "testing as an afterthought", often resulting in missing edge cases.
        *   Violates the SDLC principle of "Definition of Done" being per-feature.
        *   Manual verification becomes repetitive during development if automation isn't ready.

*   **Final Decision:** **Fully Integrated Testing.** 
    *   Every `feat` task (POV-145 to POV-148) MUST include its own `test` sub-tasks/criteria.
    *   **Justification:** This ensures that "Professional Grade" quality is baked into the code from the first commit.

---

## Phase 4: Backlog Integration

### Discussion 4: Selecting "Improvements" for v0.13.0

*   **Decision:** We reviewed `docs/backlog/improvements.md` and cherry-picked items that directly support the "UX resilience" theme:
    *   **Axios Retry Strategy:** Critical for the new Source Library fetches.
    *   **Automatic Optimistic Locking:** Vital for the Topic CRUD (using Orval mutators).
    *   **Shared Pagination:** Necessary for consistent tables in Source Library and Audit Log.
*   **Justification:** These are not just "nice to haves" but are technical enablers for the primary v0.13.0 goals.

---

## Final Planning Outcome
The resulting task list (**POV-145 to POV-150**) represents a balanced approach:
1.  **High UX Impact:** (Skeletons, Toasts, Error Pages).
2.  **Functional Completion:** (Topic CRUD, Source Item Review).
3.  **Future-Proofing:** (i18n infra, Shared components).
4.  **Security Baseline:** (Secrets Management).
