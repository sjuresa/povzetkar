### **Task 2 POV-82: Orchestration Resilience & Logging (Completed)**

**Title:** `feat(orchestration): handle PENDING items and improve logging`

**Description:**
Address two key orchestration issues:
1.  **Stuck Items:** Modify the orchestrator to pick up items in `PENDING` state and re-process them, treating them like `RETRY_LATER`. Since a new orchestration run only starts after `povzetkar.orchestration.lock-timeout` expires, no additional time threshold is needed.
2.  **Logging:** Refactor logging to avoid duplication. Ensure every log entry for a content item includes the Video ID, Duration, and URL.

**Acceptance Criteria:**
- **Test:** A test simulates a `PENDING` item left over from a crashed run and verifies it is picked up by the next run.
- **Implementation:** `OrchestratorService` query includes `PENDING`.
- **Verification:** Log inspection confirms that entries for content item processing include Video ID, Duration, and URL, and that redundant log spam has been removed.

### **Task 3 POV-83: Topic Management & Orchestration Granularity (Completed)**

**Title:** `feat(core): enable/disable topics and granular orchestration options`

**Description:**
Enhance system control by adding capabilities for topic management and granular orchestration execution.
1.  **Topic Control:** Add functionality to enable or disable specific topics. Disabled topics should be skipped by the orchestrator. **Note:** Disabling a topic only prevents processing; the topic remains visible in the UI, and existing briefings are still accessible.
2.  **Orchestration Granularity:** Modify the orchestration trigger to allow separate execution of:
    - "Process Retry/Pending Items" (re-process stuck or failed items)
    - "Summarization" (fetching and summarizing content)
    - "Briefing" (generating briefings)
    It should be possible to run any combination of these.

**Acceptance Criteria:**
- **Schema:** Add `enabled` (boolean) to `Topic` entity (default true). Create a migration script (`V4__AddEnabledToTopics.sql`) to apply this change.
- **Logic:** Orchestrator filters out disabled topics during processing.
- **API:** Update `POST /api/v1/orchestrator/run` to accept `processPending` (boolean), `summarize` (boolean), and `createBriefing` (boolean) parameters. All default to `false` if not provided.
- **UI:**
    - Admin UI: Add toggle switches (or checkboxes) to the Topics list to enable/disable them.
    - Admin UI: Add checkboxes "Process Retry/Pending Items", "Generate Summaries", and "Generate Briefings" to the "Run Orchestration" form.

### **Task 4 POV-84: Admin Dashboard Improvements & Error Persistence**

**Title:** `feat(admin): detailed content monitoring, error persistence, and smart retry`

**Description:**
Enhance the observability of the system by persisting detailed error information and exposing it in the Admin UI, along with transcript management.

1.  **Backend Persistence & Logic:**
    -   **Schema:** The `transcript` field already exists on the `YouTubeVideo` entity. Verify if the base `ContentItem` entity (mapped to the `content_items` table) has `errorMessage` (TEXT) and `errorCode` (VARCHAR) fields. If not, create a migration script to add them.
    -   **Bug Fix (Persistence):** Currently, `ContentCreationService` sets `video.transcript`, but it is not being persisted to the database. Investigate and fix this issue (likely ensuring the entity is attached/merged within the transaction).
    -   **Error Handling:** Ensure that when processing fails (e.g., 429, 503, parsing error, or Transcript Unavailable), the specific error message and code are saved to `errorMessage` and `errorCode`.
        -   **Proposed Error Codes:**
            -   `TRANSCRIPT_UNAVAILABLE`: The transcript could not be retrieved (e.g., disabled by creator).
            -   `RATE_LIMIT_EXCEEDED`: An external API (YouTube, GenAI) returned a rate limit error (e.g., 429).
            -   `UPSTREAM_SERVICE_ERROR`: An external API returned a server-side error (e.g., 5xx).
            -   `CONTENT_PARSING_ERROR`: The content retrieved from the source could not be parsed.
            -   `UNKNOWN_ERROR`: For any other unhandled exceptions.
    -   **Smart Retry:** Update the orchestration logic: When re-processing a failed item, first check if a transcript is already saved. If yes, reuse it to avoid fetching it again from the source.
    -   **API:** Create a dedicated endpoint `POST /api/v1/admin/content-items/{id}/fetch-transcript` to support the UI's AJAX call.

2.  **Admin UI Improvements:**
    -   **Columns:** Update the "Failed Items", "Pending Content Items", and "Recent Content Items with Summaries" tables to display:
        -   **Topic:** The name of the associated topic.
        -   **Transcript:** An icon/indicator showing if the transcript is stored in the DB.
        -   **Metadata:** Creation date, video duration, link to summary/briefing.
    -   **Specific Columns:**
        -   **Error Details:** Display the stored error message and code (only for "Failed Items").
    -   **Actions:** Add a "Fetch Transcript" button for items in the "Failed Content Items" and "Pending Content Items" tables to manually trigger/retry just the transcript retrieval process.
    -   **Implementation Note:** Ensure that actions (like "Fetch Transcript") use asynchronous JavaScript (AJAX/Fetch API) calls to the API endpoints rather than traditional form POST submissions. This prevents full page reloads and avoids previous implementation errors.

**Acceptance Criteria:**
    -   **DB:** `ContentItem` table has `error_message` and `error_code` columns. `YouTubeVideo` transcript is correctly persisted.
    -   **Logic:** Retrying a failed item with an existing transcript does *not* trigger a new YouTube API or AI Client call.
    -   **API:** New endpoint exists and returns appropriate success/error status for AJAX calls.
    -   **UI:** The "Pending Content Items", "Recent Content Items with Summaries", and "Failed Content Items" tables show Topic and Transcript status. Failed Items table shows Error Details.
    -   **UI:** Tables include a direct link to the generated summary or briefing (if available).
    -   **UI:** "Fetch Transcript" action works for failed and pending items.
