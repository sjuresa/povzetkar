### **Task 2 POV-82: Orchestration Resilience & Logging**

**Title:** `feat(orchestration): handle PENDING items and improve logging`

**Description:**
Address two key orchestration issues:
1.  **Stuck Items:** Modify the orchestrator to pick up items in `PENDING` state and re-process them, treating them like `RETRY_LATER`. Since a new orchestration run only starts after `povzetkar.orchestration.lock-timeout` expires, no additional time threshold is needed.
2.  **Logging:** Refactor logging to avoid duplication. Ensure every log entry for a content item includes the Video ID, Duration, and URL.

**Acceptance Criteria:**
- **Test:** A test simulates a `PENDING` item left over from a crashed run and verifies it is picked up by the next run.
- **Implementation:** `OrchestratorService` query includes `PENDING`.
- **Verification:** Logs are inspected to confirm presence of metadata and absence of spam.

### **Task 3 POV-83: Topic Management**

**Title:** `feat(topic): add enable/disable and specific orchestration support`

**Description:**
Add functionality to enable or disable specific topics. Disabled topics should be skipped by the orchestrator. **Note:** Disabling a topic only prevents automated processing; the topic remains visible in the UI, and existing briefings are still accessible. Also, add an endpoint/mechanism to trigger orchestration for a *single* topic.

**Acceptance Criteria:**
- **Schema:** Add `enabled` (boolean) to `Topic` entity.
- **Logic:** Orchestrator filters out disabled topics.
- **API:** New endpoint `POST /api/v1/orchestrator/topics/{topicId}`.
- **UI:** Toggle switch in Admin UI for topics.
