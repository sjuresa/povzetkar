### **Task 5 POV-97: Implement Orchestration Preview & Manual Status Management**

**Title:** `feat(orchestration): implement fetch-only preview and manual status management`

**Description:**
Implement a simplified "Preview" mode and allow manual status overrides.
1.  **Preview (Fetch & Count):** Trigger the standard content fetching logic. New items are persisted as `PENDING`. The process stops there and returns the count of all `PENDING` (and `RETRY_LATER`) items for the selected topics/date.
2.  **Manual Status Management:** Add a "Change Status" action (or specific buttons like "Ignore" / "Retry") to items in **Pending** and **Failed** tables. This allows setting status to `IGNORED` (to skip) or `PENDING` (to retry failed items).
3.  **Process:** The standard orchestration run skips `IGNORED` and `FAILED` items.
4.  **Database Migration:** Create a new Flyway migration script in `src/main/resources/db/migration` to add the `IGNORED` value to the `processing_status_enum`.

**Acceptance Criteria:**
- "Preview" button in Admin UI triggers fetch and updates the "Pending Items" table (via page refresh or AJAX).
- UI displays a summary message clarifying the counts (e.g., "Found 5 new items. Total pending (new + existing): 12").
- "Pending" and "Failed" tables allow changing item status to `IGNORED` or `PENDING`.
- `ProcessingStatus` enum includes `IGNORED` (updated in Java and via DB migration).

## Documentation
- **Context:** `src/main/java/com/povzetkar/quarkus/service/OrchestrationManager.java`
- **Update:** `docs/manual/admin-guide.md` (if exists) or `docs/RUNBOOK.md`

### **Task 6 POV-98: Circuit Breaker, GenAI Upgrade & Usage Refinement**

**Title:** `feat(resilience): implement circuit breaker, upgrade genai, and refine usage tracking`

**Description:**
Enhance system resilience and maintainability using insights gathered via the Context7 MCP server.
1.  **MCP Research & Upgrade:** Use Context7 to identify the latest version of `google-genai` and check if the library exposes metadata for consumed quota. Upgrade the dependency.
2.  **Refine Usage Tracking:** Modify logic to **not** increment the API usage counter when a 503 error occurs. Implement separate tracking for 503 errors.
3.  **Circuit Breaker:** Implement logic to detect consecutive 503 (Service Unavailable) errors. If $N$ consecutive errors occur, pause or stop the orchestration.

**Acceptance Criteria:**
- `google-genai` dependency is updated to the latest version.
- API usage count is NOT incremented on 503 errors.
- 503 errors are tracked separately (e.g., metric or log).
- Orchestration stops/pauses after configurable $N$ consecutive 503s.
- Unit test verifies the stop logic and usage tracking behavior.
