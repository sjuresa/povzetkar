# Version 0.15.0 Planning Process: Advanced Archive & Operational Excellence

**Status:** In Progress
**Date:** 2026-03-28

## Introduction
This document details the iterative planning process for Version 0.15.0. Following the mission of providing a "Professional Grade" experience, this version focuses on "Advanced Archive & Operational Excellence"—deepening the platform's analytical capabilities for users while hardening the infrastructure for future scalability.

## Phase 1: Strategic Evaluation & Feature Selection

During the transition from v0.14.0 to v0.15.0, we evaluated the remaining roadmap items and prioritized them based on two main goals: **Deliver immediate user value** and **Establish mission-critical observability**.

### Discussion 1: Prioritizing User UX vs. Admin Roles
*   **Initial Proposal from Roadmap:** Implement full "Admin User Management" UI (roles, statuses).
*   **Critique:** While important for multi-user scaling, individual users currently lack a way to manage their historical briefings and export their work.
*   **Final Decision:** **Pivoted to "Briefing Mastery".** We decided to prioritize the searchable "Briefing Library", "Export to Markdown/HTML", and "Real-time Source Validation". These features provide immediate tangible benefits to the core user flow.

### Discussion 2: Operational Monitoring Infrastucture
*   **Decision:** We agreed to include the full **Prometheus/Grafana** stack in the `docker-compose.yml` to track both system metrics (JVM, RAM) and business KPIs (Summaries/Briefings generated per day).
*   **Justification:** Moving from a prototype to a production-ready system requires visibility into potential bottlenecks before they impact users.

## Phase 2: Technical Design Decisions

### Discussion 3: Versioning Automation (Cross-Platform)
*   **Debated Approaches:** PowerShell scripts vs. dedicated tools (`release-it`) vs. Node.js scripts.
*   **Final Decision:** **Custom Node.js Script (`cjs`)**.
*   **Justification:** Since the project already uses Node.js for the frontend, a Node.js script is a "zero-dependency" cross-platform way to orchestrate `mvn versions:set` and the synchronization of `package.json` for both Windows dev environments and Linux CI/CD runners.

### Discussion 4: Data Retention Strategy
*   **Debated Approaches:** Dynamic UI settings vs. Static Configuration.
*   **Final Decision:** **Static Configuration with fixed 90-day retention.**
*   **Justification:** To maintain focus on user-facing features, we will skip the "Settings UI" implementation in v0.15.0 and implement the cleanup job based on `application.properties`.

## Phase 3: Testing & Use Case Philosophy

### Discussion 5: Extending the Golden Path
*   **Decision:** We are extending **[use_cases.md](../analysis/use_cases.md)** with:
    - **UC-5: Browse Briefing Archive**
    - **UC-6: Export Briefing** (Markdown/HTML focus)
    - **UC-7: Real-time Source Validation**
*   **Testing Requirement:** Every feature requires a corresponding Playwright E2E test to ensure the "Briefing Library" search and validation feedback work as expected across different viewports.

### Discussion 6: Transition to Master Test Specification
*   **Problem:** Test cases from v0.13 and v0.14 were version-specific and disconnected from the long-term regression suite.
*   **Decision:** Establish **[test_specification.md](../analysis/test_specification.md)** as the "Master" document for all system tests.
*   **Justification:** Ensures that knowledge is not lost between versions and that regression testing remains a first-class citizen in the development checklist.

## Final Planning Outcome
The resulting task list (**POV-161 to POV-166**) focuses on:
1.  **Analytical Depth**: (Briefing Archive, Advanced Filtering).
2.  **Productivity**: (Markdown/HTML Export, Shareable Links).
3.  **Observability**: (Monitoring Infrastructure, Business Metrics Dashboard).
4.  **Automation & DX**: (Node.js 24 Upgrade, Cross-Platform Versioning, Self-Cleaning Infra).
5.  **Quality Assurance**: (Master Test Suite Centralization, Playwright Automation for Validation).
