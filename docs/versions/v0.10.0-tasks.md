### **Task 10 POV-111: User Management - Extensible OIDC Integration**

**Title:** `feat(auth): implement extensible oidc authentication (google first)`

**Description:**
Implement a robust and extensible authentication system using OIDC, starting with Google as the primary provider. The system must be designed to support multiple identity providers (Facebook, X/Twitter, GitHub, etc.) in the future without schema changes.

This involves:
1.  **Multi-Provider Architecture:** Introduce a `user_identities` table to store multiple external identities for a single user (1 User : N UserIdentities).
2.  **Smart User Linking:** Logic to automatically link external accounts to existing users based on email address.
3.  **Auto-Provisioning:** Logic to automatically create new user accounts for first-time visitors who authenticate successfully.
4.  **Security Context:** Populate the Quarkus `SecurityIdentity` with roles from the internal user model.

**Technical Requirements:**
-   **Database Schema:**
    -   Create `user_identities` table with columns: `user_id` (FK), `provider` (varchar), `external_id` (varchar - e.g., 'sub'), `email`, `created_at`.
    -   Unique constraint on `(provider, external_id)`.
-   **Service Logic (`UserContextService`):**
    -   Step 1: Check if `(provider, external_id)` exists in `user_identities`. If yes, log in the associated user.
    -   Step 2: If not found, check if a user with the OIDC email already exists.
        -   If yes -> Create a new `user_identity` linking the external ID to the existing user. Log in the existing user.
        -   If no -> Create a new `User` (active=true, role=user) AND a new `user_identity`. Log in the new user.
-   **Configuration:**
    -   Configure Quarkus OIDC for Google (`quarkus.oidc.auth-server-url`, `client-id`, `credentials.secret`).
    -   Ensure `application.properties` uses environment variables for secrets.

**Acceptance Criteria:**
-   [ ] `user_identities` table exists and is correctly indexed.
-   [ ] A dedicated `UserIdentity` JPA entity is created.
-   [ ] Users can log in via Google.
-   [ ] An existing user (matching email) is linked to their Google account upon first login.
-   [ ] A new user is automatically created and linked upon first login if no email match exists.
-   [ ] The system is ready to accept other providers (e.g., Facebook) by simply adding configuration and using the existing logic with a different `provider` string.
