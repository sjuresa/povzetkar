### **Task 1 POV-102: Documentation & Process Improvements**

**Title:** `docs(process): standardize project structure and testing guides`

**Description:**
Improve developer experience and standardize processes before starting heavy feature work. This includes documenting the project structure, updating testing guides to match best practices, documenting how the agent should use the "context7" MCP server, and performing hygienic cleaning of `AGENT.md` (deduplication, optimization).

**Acceptance Criteria:**
- `AGENT.md` includes instructions for "context7" MCP server.
- `AGENT.md` is optimized (deduplicated and condensed).
- `docs/overview/project-structure.md` is created and describes the architecture/layout.
- `docs/guides/testing.md` is refactored to align with `mastering-testing.md`.
- `docs/adr/` directory is initialized with ADR-001.

### **Task 4 POV-105: Operational Logic (Min Video Duration)**

**Title:** `feat(orchestrator): filter videos by minimum duration`

**Description:**
Filter out short content (e.g., YouTube Shorts) that is not suitable for summarization. Introduce a configurable minimum duration and a new status `SKIPPED_TOO_SHORT`.

**Acceptance Criteria:**
- Configuration property `povzetkar.content.video.min-duration` is implemented.
- Videos shorter than the threshold are persisted with `SKIPPED_TOO_SHORT` status.
- These items are not re-fetched and not processed.

## Documentation
- **Context:** `src/main/java/com/povzetkar/quarkus/service/YouTubeContentFetcherService.java`
- **Update:** `ContentItem.java`, `YouTubeContentFetcherService.java`, `application.properties`

### **Task 5 POV-106: User Management - Data Model**

**Title:** `feat(auth): implement user and role entities`

**Description:**
Establish the database schema for users and roles to support authentication.
**Note:** The application delegates authentication to an external provider (e.g., OIDC). Therefore, the `User` entity should NOT store a password.

**Acceptance Criteria:**
- `User` and `Role` JPA entities are created.
- Flyway migration script creates the necessary tables.
- `User` entity includes the necessary fields (email/username, password_hash, active).
- `User` entity does NOT include a password field.

## Documentation
- **Context:**
  - `src/main/java/com/povzetkar/quarkus/model/`
  - `src/main/resources/db/migration/`
- **Update:** 
  - `User.java`, `Role.java`, `src/main/resources/db/migration/V5__CreateUserTables.sql`

### **Task 7 POV-108: User Management - Multi-tenancy Backend**

**Title:** `feat(backend): implement multi-tenancy for topics and sources`

**Acceptance Criteria:**
- `Topic` and `ContentSource` tables have `user_id` FK (via migration).
- Panache queries filter by current user.
- Integration tests verify data isolation between users.
