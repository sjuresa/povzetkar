## Task Breakdown

### Task 1 POV-134: (Completed) Frontend Architecture ADR
- **Description:** Create a formal Architectural Decision Record for the frontend stack. This must define:
  1. Framework choice.
  2. Styling philosophy.
  3. State management strategy.
  4. API client and response envelope handling.
- **Documentation:**
  - `Context`: We need a consistent, production-grade foundation for all future UI work.
  - `Update`: Create `docs/adr/0004-frontend-architecture.md`.
- **Note:** Upon completion of this ADR, the Definition of Done for Task POV-136 must be updated to reflect the chosen technology stack.

### Task 2 POV-135: (Completed) Monorepo Transition
- **Description:** Restructure the repository to support both Backend and Frontend projects efficiently.
- **Documentation:**
  - `Context`: Decoupled development requires a clear directory hierarchy.
  - `Update`: Move existing code to `/backend`, update Maven root for sub-modules, and adjust CI/CD pipelines.

### Task 3 POV-136: (Completed) Frontend Project Initialization (Base)
- **Description:** Scaffold the frontend application in `/frontend` according to ADR-0004.
- **Definition of Done:**
  - [x] React/Vite/TypeScript/vite-react-ssg scaffold complete.
  - [x] Tailwind CSS and Shadcn/UI configuration.
  - [x] Vitest and Playwright base configuration.
  - [x] Initial folder structure (components, hooks, routes, services).

### Task 4 POV-137: (Completed) Frontend API & Logic Foundations
- **Description:** Implement the type-safe API client and global interceptors.
- **Definition of Done:**
  - [x] Orval integration consuming `openapi.json` from backend.
  - [x] TanStack Query (via Orval) hooks generated and ready.
  - [x] Global API Interceptor implemented for:
    - [x] Envelope parsing (`{ data, meta, error }`)
    - [x] Request tracing (`X-Correlation-ID`)
    - [x] Idempotency (`Idempotency-Key` for `POST /commands/*`)
    - [x] Standard error handling (401, 403, 429, 503 with `Retry-After` support)
  - [x] Optimistic Locking (`If-Match`) handling implemented within mutations.

### Task 5 POV-138: (Completed) Auth & UI Shell (First Paint)
- **Description:** Implement authentication flow and the master application layout.
- **Note:** This task delivers the "First Paint" - a working visual shell.
- **Definition of Done:**
  - [x] OIDC Login flow and session state management (Zustand).
  - [x] TanStack Router (type-safe) base configuration and auth guards.
  - [x] Master Layout implementation (Sidebar, Header, Content area).
  - [x] Responsive navigation and branding elements.

### Task 6 POV-139: (Completed) Dashboard MVP
- **Description:** Implement the first interactive screen fetching data from `GET /api/v1/dashboard`.
- **Definition of Done:**
  - [x] Dashboard route implemented.
  - [x] Widgets for active topics and weekly stats rendered.
  - [x] Recent briefings list displayed with navigation.

### Task 7 POV-140: Real-time Event Stream (SSE)
- **Description:** Integrate the v0.11 SSE stream into the UI to provide live feedback on orchestration jobs.
- **Definition of Done:**
  - [ ] EventSource client implemented in the frontend.
  - [ ] Toast or notification component for "Job Status Changed" events.
  - [ ] Real-time status badges in tables if applicable.

### Task 8 POV-141: Continuous Deployment & Scanning Hardening
- **Description:** Optimize the build and deployment process for the full stack and ensure the new frontend project is integrated into the security pipelines.
- **Definition of Done:**

  - [ ] Nginx or integrated Quarkus static serving configured for production.
  - [ ] Frontend dependency scanning (Trivy/Snyk) integrated into GitHub Actions.
  - [ ] Update `RUNBOOK.md` with full-stack deployment instructions.

### Task 9 POV-142: Audit Log Admin UI
