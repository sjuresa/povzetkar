## Task Breakdown

### Task 1 [POV-161]: Briefing Library & Archive
- **Title:** `feat(briefing): Implement searchable archive with advanced filtering and grouping`
- **Priority:** **P0**
- **Description:** 
  Transform the simple briefing list into a powerful archive.
  - **Search**: Lucene/Database-backed search on briefing content and metadata.
  - **Filters**: Date-range, Topic-based, and Source-count filters.
  - **UX**: Paginated results with i18n support and **mobile-first responsive layouts**.
- **UI Schema (ASCII Mockup)**:
  ```text
  [ Briefing Library ]-----------------------------------
  | [Search...] [Topic v] [Date v] [Source v] [Reset] |
  +-----------------------------------------------------+
  | Date     | Topic      | Summary Head | Actions      |
  |----------|------------|--------------|--------------|
  | 28.03.26 | Finance    | Markets...   | [View] [Exp] |
  +-----------------------------------------------------+
  | [ < 1 2 3 > ]                      Items: 50/1200   |
  ```
- **Resilience & Error States**:
  - **DB/Lucene Failure**: Show a "Search temporarily unavailable" toast and fallback to non-filtered list if possible.
  - **Empty Results**: Clear "No briefings found" state with a "Clear all filters" button.
- **Context / Documentation:**
  - [../analysis/use_cases.md](../analysis/use_cases.md) (UC-5)
  - [../analysis/frontend-specification.md](../analysis/frontend-specification.md) (Define Library view & filters)
  - [../analysis/api-design.md](../analysis/api-design.md) (New search/filter endpoints)
- **Required Skills**: `@[skills/frontend-design]`, `@[skills/nextjs-react-expert]`, `@[skills/api-patterns]`, `@[skills/testing-patterns]`
- **Acceptance Criteria:**
  - [ ] Briefings table supports multi-column sorting and keyword search.
  - [ ] Date-range picker filters results correctly.
  - [ ] **test(e2e)**: Verify search result accuracy for specific keywords (PW-04).
  - [ ] **UX**: Verify legible rendering on mobile viewports.
  - [ ] **docs**: Update `frontend-specification.md` with the new Library UI layouts.

### Task 2 [POV-162]: Export & Share Capabilities
- **Priority:** **P1**
- **Title:** `feat(briefing): Implement Markdown/HTML export and internal link sharing`
- **Description:**
  Allow users to take their briefings outside the platform.
  - **Exporting**: Generate `.md` and `.html` files for download.
  - **Sharing**: Generate unique, secure internal URLs for briefings (UUID-based, auth-guarded).
- **Resilience & Error States**:
  - **Generation Fail**: If Markdown/HTML generation fails (e.g., Disk Full), show a "Export failed" error toast and log the cause for admin review.
  - **Unauthorized Access**: Redirect unauthenticated shareable link attempts to the Login page with a "Restricted Content" notice.
- **Context / Documentation:**
  - [../analysis/use_cases.md](../analysis/use_cases.md) (UC-6)

- **Acceptance Criteria:**
  - [ ] Export buttons functional on Briefing Detail view.
  - [ ] Downloaded Markdown preserves all formatting and links.
  - [ ] **Security**: Verify shareable links are inaccessible to unauthenticated users or properly masked.
  - [ ] **docs**: Document the Export API and sharing logic in `api-design.md`.
