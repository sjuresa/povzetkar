# v0.9.0 Planning Process: Operational Refinement & Admin Tools

**Status:** Finalized
**Date:** 2026-02-05

## 1. Review of Previous Retrospective
*Action:* Reviewed learnings from v0.8.0.
*Key Takeaway:* The system is functional as a standalone app, but operational visibility and resilience need improvement before scaling to multiple users.

## 2. High-Level Goals
Based on the revised roadmap and immediate operational needs, the goals for v0.9.0 are:
1.  **Enhance Admin Experience:** Improve the Admin UI with actionable insights (GenAI Usage, Orchestration Preview) and fix usability bugs (Timezones).
2.  **Data Management:** Implement pagination for history tables to handle growing datasets.
3.  **Improve System Resilience:** Implement patterns to handle external API failures (Circuit Breaker for 503s).
4.  **Formalize Methodology:** Document the development methodology explicitly.
5.  **Research Future Capabilities:** Investigate MCP (Model Context Protocol) for better agent context.

## 3. Testing Strategy
*   **UI Features (Usage, Preview):** Will be tested via standard `@QuarkusTest` integration tests (e.g., `AdminResourceTest`). *Note: We will avoid the `BaseUITest` pattern which failed in v0.6.2 and instead use explicit transaction management or `@TestTransaction` where applicable.*
*   **Resilience (Circuit Breaker):** Requires a unit test with mocked external service failures to verify the backoff/stop logic.
*   **Timezone Fix:** Manual verification is critical here, but we will add unit tests for the new `DateTimeService` to ensure conversions are correct.

## 4. Task Breakdown

### 4.1. Operational Improvements (The "New Ideas")
*   **feat: Display GenAI Usage per Key:** Show number of calls made with each API key for the current day (defined as PST, to align with API quotas).
*   **fix: Timezone Display in Admin History:** Ensure all times are displayed in the user's configured IANA timezone (e.g., Europe/Ljubljana) or as relative time.
    *   *Dependency:* Implement **Centralized Date/Time Formatting Service** (from Backlog).
*   **feat: Pagination for Admin History:** Add "Previous/Next" controls to history tables.
*   **feat: Implement Orchestration Preview & Manual Status Management:** Implement "Fetch & Count" mode and allow status changes.
    *   *Backend:* Trigger fetch logic, persist as `PENDING`, stop, and return counts of pending items.
    *   *UI:* "Preview" button triggers fetch. Add "Change Status" (Ignore/Retry) actions to "Pending" and "Failed" tables.
*   **feat: Circuit Breaker for 503 Errors:** Implement logic to pause or stop orchestration after $N$ consecutive 503 errors from YouTube/GenAI.

### 4.2. Documentation & Process
*   **docs: Create Methodology Document:** Consolidate `07_development_methodology_comparison.md` and `11_development_checklist` principles into a definitive `docs/process/methodology.md`.
*   **spike: Research MCP Context Integration:** Analyze how the agent can use a Model Context Protocol server to fetch the latest documentation dynamically.

## 5. Risk Assessment
*   **Timezone Handling:** Dates are notoriously tricky. We must ensure the server sends UTC and the client/UI renders correctly, or the server renders explicitly in the configured timezone.
*   **Circuit Breaker:** Risk of stopping valid long-running processes if false positives occur. Needs careful configuration.

*   [ ] `mvn clean verify` passes.
*   [ ] New features (Preview, Usage, Status Management) are visible in Admin UI.
*   [ ] Pagination is working.
*   [ ] Methodology document is created.
