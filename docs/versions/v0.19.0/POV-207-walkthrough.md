# POV-207 Walkthrough — Close public exposure of `/q/*` technical endpoints

**Task:** [POV-207](https://jumis.myjetbrains.com/youtrack/issue/POV-207) (Bug, Critical) · **Branch:** `POV-207` → `v0.19.0` · **Date:** 2026-09-25

## 1. What was done

While planning POV-206 (environment upgrade), a check on the Prometheus scrape token revealed that production (`https://povzetkar.juresa.si`, served from the local Docker stack) answered `/q/metrics`, `/q/health` and `/q/openapi` with **200 to anyone**. Root cause: `%prod.quarkus.micrometer.export.prometheus.security-enabled` / `…bearer-token` are not Quarkus properties (`PrometheusConfigGroup` only has `enabled`, `path`, `default-registry`) and were silently ignored; `/q/*` matched no `quarkus.http.auth.permission.*` rule; Caddy and the Cloudflare tunnel forward everything on `app:8080`. POV-206 was paused and this task preempted it.

* **Quarkus management interface** — `quarkus.management.enabled=true` (build-time, profile-free). Metrics, health and OpenAPI now live only on port 9000 (9001 in tests); on 8080 they return 404 (`SpaRoutingHandler` already excluded `/q`, so no SPA fallback interferes). OpenAPI follows automatically (`quarkus.smallrye-openapi.management.enabled` defaults to `true`).
* **Consumers re-pointed** — `Dockerfile` `HEALTHCHECK` → `localhost:9000/q/health/ready`; `prometheus.yml` target → `app:9000`; `docker-compose.prod.yml` lists `9000` under `expose` (Docker network only, no `ports:`).
* **Removed, not repaired** — the two non-existent properties (+ `%dev`/`%test` variants) and their misleading comment, the redundant `quarkus.micrometer.export.prometheus.path`, `METRICS_SCRAPE_TOKEN` (app + Prometheus, prod + dev compose), Prometheus `bearer_token`, and the non-existent `--enable-feature=expand-external-variables` flag (WARN on every start).
* **Tests** — new `ManagementInterfaceTest` (9 tests: `/q/metrics`, `/q/health`, `/q/health/live`, `/q/health/ready`, `/q/health/started`, `/q/openapi` → 404 on the main port; metrics and OpenAPI → 200 and readiness answers **HEAD** — what the healthcheck binary sends — on the management port). `OpenApiGeneratorTest` and `ApplicationHealthIT` re-pointed to the management port.
* **Production deploy** from commit `a747dba7` with a rollback tag, verified externally (see §5).
* **Docs** — RUNBOOK §6.1/§6.2 (port 9000), §10.3 (`--no-deps`, rollback tag), §13.2 rewritten (network boundary, Grafana-as-bridge caveat, verification commands), env tables; CHANGELOG `Security`; TC-MON-001; backlog (4 new entries, 1 updated); lessons-learned + `lessons/infrastructure-ops.md`.
