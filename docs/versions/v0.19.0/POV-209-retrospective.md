## 2. Deviations & why

- The CI commit went in before its YAML check ran (a failing check chained with `;`). Harmless here (re-validated), but the pattern — `check ; commit` instead of `check && commit` — is exactly how an unverified change slips through.
- **The pre-commit review was first misapplied.** The agent classified the task as docs-only and ran only the consistency check (one stale reference found) — although the task changed `ci.yml`, i.e. executable code. The PO asked whether a code review had run; `/code-review high` then ran in a subagent (the new 2.5a default) and returned 12 verified findings, 2 high: 2.5b sat before the commit (no CI run can exist yet), and the YouTrack record at 2.9 ran before the walkthrough (2.10) and the PR loop, so its comments and work items could never be final. Also: the deploy gate named "the exact commit" without a way to prove it (`headSha`), the Step 8 exit condition contradicted its own no-response rule, the local Trivy image was pinned by a mutable tag in the very lesson that says "by digest", and the incident record missed the intermediate `@v0.28.0` tag. All fixed before the push. The PO then removed the docs-only exemption altogether: `/code-review high` runs for every task, documentation included — this task's defects were mostly in documents.
- **Second review round (PO request):** 10 further findings, 1 high (the Step 8 thread command did not exist), all fixed — see the walkthrough, D6. Checklist Phase 2 gained an explicit execution order, 2.8a (push & PR loop) and 2.15 (YouTrack record, last).
- **Third review round (PO request):** 9 further findings, 1 high — the Step 8 loop could never exit (a reply does not resolve a thread; the loop now resolves threads via GraphQL). A broken scripted edit from round 2 had also duplicated the walkthrough's Traceability section; the review caught it before the commit.
- **Fourth review round (PO request) and the scripted-edit rule:** 8 further findings, none high — see the walkthrough, D8. The PO asked whether every disk write must still be verified: POV-204 had dropped read-back on the premise that file tools fail loudly, which does not hold for the scripted `node` edits this task used (they silently duplicated a section and dropped a `**`). `verification.md` now requires inspecting every scripted/shell edit.
- **Fifth review round (whole task diff, PO rule):** 7 findings, none high — see the walkthrough, D9. It also showed that the `code-review` skill, called without an explicit base, reviews only uncommitted changes; the protocol now requires the base to be passed.
- **Sixth review round (PO request):** 7 findings, none high — see the walkthrough, D10. The most consequential one was factual: the incident record ignored the advisory's exposure window; with it, 5 CI runs were exposed (3 green) instead of an unqualified "20 runs on poisoned tags", and `@v0.28.0` was pinned only after the window closed.

## 3. Technical findings

- **A bot reviewer can be invisible to the review loop.** On #279 Greptile posted only a PR conversation comment (confidence, risk, "Last reviewed commit"); on #278 its only output was a review whose body said "Your trial has ended" — not a review at all. A loop reading only threads would have declared "no findings" in both cases; this task first misread #278 as a real review three times before the fourth round checked the body; and the documented thread command (`gh pr view --json reviewThreads`) does not even exist in gh 2.101.0 — the old Step 8 had never been executable as written. Check *all* forms a reviewer uses before trusting a "clean" loop.
- **CI Trivy is the stronger pre-deploy scan** — fresh base, FS + image, on every PR/push — so local Trivy (slow, OOM risk parallel to tests) is only needed without a CI run. The real pre-deploy gap was never the tool; it was deploying a commit without a green, recent CI run and building on a stale local base.
- **The security scanner itself was the attack path.** `trivy-action` tags were poisoned for ~12 h in March 2026; our CI ran 5 times on `@0.24.0` inside that window (3 green runs reached the Trivy steps) and has used `@master` since. Establish the exposure window from the advisory before counting exposure — a count over the whole day overstated it fourfold. Pin by commit SHA of an immutable release, dereferencing annotated tags (the tag object SHA ≠ commit SHA). Exposure was small only by configuration luck (few secrets in the job) — keep secrets out of jobs that do not need them.
- **Unverified process claims propagate.** "Process/tooling tasks are exempt by precedent" was written by POV-204 from a single case (POV-203) and contradicted by five earlier process tasks with CHANGELOG entries; this task first repeated it before checking. AGENT.md principle 2 (evidence for claims about the process itself) applies to the agent's own protocol text.
- **One review round is not enough for normative text — and fixes need review too.** The second `/code-review high` round (PO request) found 10 more defects, including the round-1 fixes themselves: 2.5b and 2.9 had only gained wording ("after the push", "after the walkthrough") while staying *before* the work they depend on, and the pre-commit review ran before the close-out documents, so the documents D5 had just brought into scope were still never reviewed. Wording that points forward in time is a sign the step sits in the wrong place — fix the order, not the sentence. Round 3 still found defects in round-2 fixes (a partial execution order, an unreachable exit condition): each round of fixes to normative text needs its own review (now required: `/code-review high` again on the whole task diff after every fix round — not only on the fixes, because every round here also found older defects the previous rounds had missed). Six rounds: 12 → 10 → 9 → 8 → 7 → 7 findings, high ones only in rounds 1–3. Even the reviewer's own counts need checking — its CI run count was off by one.
- **Scripted edits need the check the file tools make unnecessary.** Several `node -e` replacements failed silently (escape bug, CRLF mismatch, a lost `**`); the Edit tool's exact-match failure is what made "no read-back" safe, and scripts do not have it. Prefer the Edit tool for normative text; after any scripted edit, look at the diff.
- **A grep-based consistency check cannot review a process.** It finds dangling references, not ordering errors or contradictions between rules — both high findings were sequencing defects invisible to grep. Documents need the same review as code; for normative documents the review also checks contradictions, step ordering and executability (now part of 2.5a).
- **`/code-review high` works inside a subagent** (Skill tool, forked execution, ~78k subagent tokens, ~5 min), returning only verified findings to the main session — the feed-forward question from the Brainstorm is answered.
- **The YouTrack MCP cannot manage versions** (only select existing Fix-version values) — creating and releasing a version stays a PO step.
