# POV-209 Walkthrough — Process: reviewer-agnostic PR loop, pre-commit review, pre-deploy Trivy, YouTrack record, task pause, release finalisation

**Task:** [POV-209](https://jumis.myjetbrains.com/youtrack/issue/POV-209) (Task, Major) · **Branch:** `POV-209` → `v0.19.0` · **Date:** 2026-09-26

## 1. What was done

The interim process rules the PO approved on 2026-09-25 (after POV-207; exercised by POV-208 and POV-206) became the permanent protocols, and the gaps found while preparing to finalise v0.19.0 were closed. One code change: the Trivy GitHub Action is pinned.

- **CI (`fix(ci)`, `53b4868c`):** both Trivy steps in `.github/workflows/ci.yml` moved from `aquasecurity/trivy-action@master` to `@ed142fd0673e97e23eac54620cfb913e5ce36c25 # v0.36.0` (immutable release, commit dereferenced from the annotated tag; it pins `setup-trivy` to the advisory's safe v0.2.6 internally) with `version: 'v0.74.0'`. Evidence gathered on the way: in the March 2026 TeamPCP compromise 76/77 `trivy-action` tags were force-pushed to credential-stealing code (GHSA-69fq-xp46-6x23); `ci.yml` used the tag `@0.24.0` then; on 19–20 March CI ran 20 times on tags (19 × `@0.24.0`, 1 × `@v0.28.0`; counted per run commit) and 5 times on `@master`. Inside the advisory's `trivy-action` window (03-19 ~17:43 → 03-20 ~05:40 UTC) fell **5 runs, 3 green** (`af64c0b0`, `3e3ae998`, `75bf5a09`) — they reached the Trivy steps, so execution of the malicious action is highly probable; run logs have expired (HTTP 410). `4d71a3cc` (2026-03-20 07:42 CEST, after the window) moved to `@v0.28.0` and `cd55e106` (08:01) to `@master` "to bypass broken tags". Only `TEST_DB_*` and a read-only `GITHUB_TOKEN` were in the job; `GOOGLE_API_KEYS`/`YOUTUBE_API_KEY` were never referenced by `ci.yml`.
- **`workflow-mandatory.md`:**
  - **Step 1** — the Brainstorm ends with the PO's approval of the task definition; Time Log rules for machine waits ≥ 10 min (`[wait: …]` → Testing) and PO pauses (≥ 30 min or declared → `[paused: PO]`, excluded); new *Pausing, resuming and session hand-over* (WIP = 1 stated explicitly).
  - **Step 7** — *Pre-commit Review* (every task, documentation included; subagent by default, PO separate session as fallback); *YouTrack task record* (States, three verbatim comments read back, Fix version, Estimation, work items); the unfounded "process/tooling tasks are exempt by precedent" CHANGELOG clause removed.
  - **Step 8** — reviewer-agnostic: inline threads *and* the reviewer's summary comment (on #279 Greptile posted only a conversation comment, which the old loop never read; on #278 its only output was a "Your trial has ended" review — now explicitly treated as no response), thread state via GraphQL (the documented `gh pr view --json reviewThreads` does not exist in gh 2.101.0), wait for the summary on the last pushed commit, ~15 min no-response rule, late reviews still handled.
- **`verification.md`:** new *Pre-deploy Verification* — CI is the scan (a green `push`/`workflow_dispatch` run that built the deployed commit — a PR run builds the merge ref; re-scan when it started more than 7 days ago), local Trivy only by exception, `build --pull`, HIGH/CRITICAL stops the deploy, `.trivyignore` entries only with PO approval; *During Execution* — scripted/shell edits must be inspected (`git diff`) after every change (Edit/Write tool writes need no read-back).
- **Checklist v3.4:** explicit Phase 2 execution order; 2.0 (YouTrack `In Progress`, Brainstorm boundary); new 2.5a (after the close-out documents) / 2.5b (after the push); new 2.8a Push & PR Review Loop; 2.9 = PO confirmation only; new 2.15 YouTrack Task Record (last); 1.2 marked as a PO step, new 3.1a Supply-chain Audit (`.trivyignore` + pinned Trivy versions), 3.1b Fix-version check, 4.2 explicit merge criteria, new 4.4 release deploy and 4.5 YouTrack release (PO step). No renumbering.
- **Single source for the release:** `06_development_process.md` §4.2 (still described `v0.5` branches and roadmap-driven releases) and `methodology.md` Phases 3/4 keep only the intent and point to the checklist.
- **RUNBOOK:** §8.2 — CI is the pre-deploy scan, local scans by exception, image pinned to `aquasec/trivy:0.74.0@sha256:62b1e65e…` (tag and digest verified on Docker Hub); §10.3 — points to Pre-deploy Verification.

- **Also:** `AGENT.md` protocol index; backlog — "WIP > 1 execution: git worktree + live task file per task" and "Pin the remaining GitHub Actions by commit SHA + Dependabot"; CHANGELOG — POV-209 (Security + Documentation) and the missing POV-203/POV-204 entries.
