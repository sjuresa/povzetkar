# Version 0.17.0 Tasks: Administrative Control & User Onboarding

**Version:** 1.0
**Status:** Active
**Project Task:** POV-182 (Planning)

## Goals
- Close the operational governance gap with a first-class **Admin User Management** surface.
- Eliminate uncontrolled sign-up by introducing an explicit **Account Activation State Machine**.
- Give administrators **live job control** (cancel, restart, audit) for background orchestration.
- Harden the transcript ingestion pipeline against IP rate-limiting via **multi-provider abstraction + jitter**.
- Polish two long-standing UX friction points: **external links** and **session expiry**.

      - `email` (substring search)

  ```text
  [ User Management ]-----------------------------------------------------------
  | Filter: [Status ▼]   Search: [ email substring... ]                         |
  |-----------------------------------------------------------------------------|
  | Email ▲              Status              Last Login    Created    Actions  |
  | user@example.com     ENABLED             2 days ago    3 mo ago   [Disable]|

Destructive actions (`Disable`, `Reject`) render as **red buttons**, no confirmation modal — both transitions are reversible in one click (`Enable`/`Re-approve`) so misclick recovery is trivial. Pessimistic refetch on every action (no optimistic UI in v0.17.0).

  - **Stale list after action:** action mutation completes → React Query invalidate + refetch list (pessimistic pattern, matches AuditLogPage convention).

  - **Demo system user seed:** `demo@povzetkar.local`, `accountStatus=ENABLED`, owns one demo topic with 1-2 content sources. No OIDC identity. UI must function correctly when demo topic has no content (empty briefing list).
  - **OIDC creation flow** ([UserContextService.createNewUser](../../../backend/src/main/java/com/povzetkar/quarkus/service/UserContextService.java#L111)): every new user → `accountStatus = PENDING_APPROVAL` + `demo` role. **No config flag** — approval always required.   - **Last-admin disable:** 409 with `code=LAST_ADMIN_REQUIRED`.
  - **Demo topic empty:** SPA must render gracefully when demo user has zero topics or zero briefings (empty list, no errors).

### Task 4 [POV-187]: Session Expiry Handling
- **Priority:** **P1**
- **Title:** `fix(auth): 401 interceptor stores returnTo in sessionStorage and redirects to landing`
- **Description:**
  Replace the "glitch in the matrix" experience on session expiry per [ADR-0010](../../adr/0010-session-expiry-return-to.md). The existing `case 401` in the Axios interceptor ([client.ts:154](../../../frontend/src/api/client.ts#L154)) already calls `clearAuth()` but throws the error upward to the error boundary. This task replaces that behaviour with a graceful redirect flow.

  There is no `/login` SPA route — authentication is server-side OAuth via `login()` → `/auth/login`. `returnTo` is preserved across the OAuth round-trip via `sessionStorage` (permanent decision, see ADR-0010).

  - **`client.ts` changes (interceptor):**
    1. Import `router` singleton from `../router`.
    2. On 401: validate current path is not `/` (loop guard). Save `sessionStorage.setItem('auth.returnTo', pathname + search)`. Call `clearAuth()`. Call `router.navigate({ to: '/', search: { notice: 'session_expired' } })`. Do **not** re-throw — prevents error boundary.
    3. Path validation before storing: must start with `/`, no `//`, no scheme.
  - **`LandingPage.tsx` changes:**
    1. Extend `validateSearch` to accept `notice: 'session_expired' | 'restricted' | undefined`.
    2. Add `session_expired` notice rendering using `auth.session.expired` i18n key.
    3. In `useEffect`: if `isAuthenticated && sessionStorage['auth.returnTo']` exists → consume (removeItem) + `router.navigate({ to: returnTo })`.
- **Resilience & Error States**:
  - **Redirect Loop:** Guard: if `router.state.location.pathname === '/'`, skip navigate on 401.
  - **Invalid Return Path:** Validate before store; discard silently if invalid — user lands on dashboard after login.
  - **401 from `/auth/*`:** Backend auth endpoints never pass through the Axios interceptor (they use `window.location.href` directly); no special case needed.
- **Context / Documentation:**
  - [ADR-0010 — Session Expiry returnTo via sessionStorage](../../adr/0010-session-expiry-return-to.md)
  - [planning-process.md § Discussion 5](./v0.17.0-planning-process.md)
  - [v0.17.0-i18n-audit.md § 4](./v0.17.0-i18n-audit.md)
  - Existing: [client.ts:154](../../../frontend/src/api/client.ts#L154), [LandingPage.tsx](../../../frontend/src/routes/LandingPage.tsx)
- **Required Skills**: `@[skills/frontend-design]`, `@[skills/security]`
- **Performance Budget**:
  - **Redirect latency:** < 300ms from 401 response to landing page render.
- **Acceptance Criteria:**
  - [ ] 401 responses no longer trigger `ErrorPage`.
  - [ ] `sessionStorage['auth.returnTo']` set to current path before redirect.
  - [ ] Landing page shows `session_expired` notice using `auth.session.expired` i18n string.

### Task 6 [POV-189]: Transcript Multi-Provider Pilot (Supadata + Jitter)
- **Priority:** **P0**
- **Title:** `feat(ingest): introduce TranscriptProvider abstraction with Supadata pilot and YouTube jitter`
- **Description:**
  Refactor transcript fetching per [ADR-0009](../../adr/0009-multi-provider-transcript-strategy.md). Built-in spike phase (Phase 1) validates the Supadata API before implementation begins.

  **Spike fallback decision (from planning interview):** If the Supadata spike reveals the API is unsuitable (wrong format, incompatible contract, unreliable), POV-189 **shrinks to scope A-lite-minus**: deliver the `TranscriptProvider` abstraction + `YouTubeLegacyTranscriptProvider` + jitter + quota tracking — without a second provider. Supadata integration deferred to v0.18.0. Do NOT defer the abstraction itself.

  **Quota tracking scope (A-lite, from planning interview):** Backend only. `transcript_provider_quota_usage` table + `GET /api/v1/admin/transcript/providers` endpoint so the backend knows remaining quota. Frontend admin component (`admin.transcript.*` i18n keys) deferred to v0.18.0 alongside Grafana alerting.

  - **Phase 1 (Spike, ~4h):** Validate Supadata API contract (auth, rate limits, response shape, error codes, videoId vs URL). Update ADR-0009 status from `Proposed` to `Accepted` with concrete implementation notes. **Gate:** if Supadata unsuitable, proceed with scope A-lite-minus.
  - **Phase 2 (Implementation, ~8h):**
    - `TranscriptProvider` interface: `name()`, `fetch(String videoUrl)`, `remainingQuota()`.
    - `YouTubeLegacyTranscriptProvider`: refactor existing `YouTubeTranscriptService`; add jitter (`Thread.sleep` on blocking executor, configurable via `transcript.providers.youtube-legacy.jitter.min-ms` / `.max-ms`; `0/0` disables for tests).
    - `SupadataTranscriptProvider` (conditional on spike success).
    - `TranscriptOrchestrator`: ordered fallback chain via `transcript.providers.order`; replaces `YouTubeTranscriptService` at injection points in `ContentCreationService` and `ContentItemService`.
  - **Phase 3 (Hardening, ~4h):**
    - `transcript_provider_quota_usage` table: `(provider_name, period_yyyy_mm, fetches_count)` — upsert on each fetch.
    - `GET /api/v1/admin/transcript/providers` endpoint: returns per-provider `{name, enabled, fetchesThisMonth, limit}`. Gated by `V_ADMIN_DASHBOARD_VIEW`.
    - Micrometer counters per provider: `transcript.fetch.attempts`, `.successes`, `.failures{reason}`, `.quota_exhausted`.
    - Config flags: `transcript.providers.supadata.enabled` (default `false`), `transcript.providers.supadata.api-key`.

- **Resilience & Error States**:
  - **Provider Timeout:** 10s timeout per provider call; on timeout, fall through to next provider.
  - **Quota Exhausted:** Log warning, fall through, increment `transcript.fetch.quota_exhausted{provider}` counter.
  - **All Providers Failed:** Returns empty transcript; `ContentItem` marked `FAILED` (existing flow).
  - **Jitter Disabled:** `min-ms=max-ms=0` → no delay (test mode).
  - **Supadata disabled:** If `transcript.providers.supadata.enabled=false`, provider is excluded from the chain entirely — fallback never tries it.
