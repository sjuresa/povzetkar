## 1. Review of Previous Retrospective
*Action:* Reviewed learnings from v0.11.0.
*Key Takeaway:* The explicit "Frontend Spec -> API Contract" flow was highly successful. However, async execution in integration tests and MDC propagation to worker threads remain technical focal points. We must ensure the new monorepo structure doesn't break these patterns.

## 2. High-Level Goals
The primary theme of v0.12.0 is **Frontend MVP & Monorepo Foundations**. Following the successful specification phase in v0.11, the project now pivots to delivering a tangible, deployable UI.

### Primary Objectives
1.  **Monorepo Migration:** Restructure the project to house both Backend and Frontend in a single repository with clear boundaries.
2.  **Frontend Architecture (ADR):** Formally decide on the FE stack (Framework, CSS, State) to ensure production-grade foundations.
3.  **BFF Integration:** Connect the UI to the v0.11 REST API, specifically the Dashboard and SSE event stream.
4.  **Security & Scanning:** Integrate OIDC Login into the SPA and extend security scanning (Trivy/Snyk) to the new frontend project.
5.  **MVP Deployment:** Ensure the entire stack (FE + BE) can be built and deployed via single Docker orchestration.

## 3. Testing Strategy
- **Frontend Unit Testing:** Focus on critical logic such as permission resolvers, state management, and API interceptors.
- **End-to-End (E2E) Testing:** Introduction of a basic E2E framework (e.g., Playwright) to test the Login flow and Dashboard hydration.
- **Integration Impact:** Backend `RestAssured` tests remain the source of truth for API stability during the transition to a decoupled frontend.

## 4. Architectural Decisions (ADRs)
- **ADR-004:** Frontend Architecture Choice (Vite/React vs. Next.js, Styling, State). This is the first task of the version.

## 5. Task Breakdown Strategy
The development of the Frontend MVP is divided into foundational infrastructure and vertical feature slices:
- **Infrastructure:** Monorepo setup, Frontend scaffolding, and Auth integration.
- **Dynamic Integration:** SSE stream implementation for real-time reactivity.
- **Vertical Features:** Dashboard MVP and Admin Audit Log table as the first functional implementations.
- **Ops:** Production Docker hardening and CI/CD security scanning.

## 6. Risk Assessment
- **Monorepo Build Friction:** Ensuring Maven and NPM work harmoniously in CI/CD without significant overhead or environment-specific failures.
- **SPA Security:** Correctly handling OIDC tokens, session lifecycle, and CSRF protection in a completely decoupled environment.
- **SSE Stability:** Ensuring the Server-Sent Events stream remains stable across reverse proxies and within Docker containers.
