# Version 0.16.0 Planning Process: User Experience Focus
 
**Status:** Concluded
**Date:** 2026-04-01
 
## Introduction
This document details the iterative planning process for Version 0.16.0. Following the mission of "Hardening & Polish", this version focuses on "User Experience Focus"—lowering the barrier to entry for new users (Onboarding) and enhancing the value of the intelligence gathered.

### Phase 2: Technical Hardening & NFRs
- **Baseline Audit (April 01, 2026):** Performed empirical latency audit on `povzetkar.onrender.com`. Confirmed TTFB/FCP within 2025 standards, but identified frontend bundle size (1.2 MB) as the primary bottleneck.
- **Backend Optimization Audit:** Manual review of `BriefingApiResource.java` and `BriefingMapper.java` revealed a critical **N+1 problem** in paginate listing. A new high-priority task (**POV-174**) was added to the roadmap to resolve this before bundle optimization.
- **ADR Refinement:** Clarified sharing logic in `ADR-0005` following CR feedback. Confirmed that `public_uuid` must reside on the **Summary** entity to allow granular individual sharing, distinct from the `uuid` already present on **Briefing**.
- **Task Granularity:** Refactored estimates from high-level buckets to individual task-level accuracy.

### Discussion 1: Conversion & Branding
*   **Strategic Pivot:** Updated Landing Page CTA from "Get key insights" to "Create your first briefing" to emphasize automation.
*   **Terminology:** Replaced technical "RSS" with "Blogs and other sources".
 
### Discussion 2: UUID Lifecycle (Summary Sharing)
*   **Final Decision:** **Resettable UUID on "Unshare".** 
*   **Security:** Invalidates leaked links by generating a fresh UUID upon re-sharing.
 
### Discussion 3: Gamification & Onboarding
*   **Context:** We considered passive empty states but decided on a **5-step Interactive Checklist** to drive user engagement.
*   **Decision:** Implement a non-blocking Dashboard checklist (Topic -> Source -> Trigger -> Read -> Share) with a gamified progress bar. Persistence via **LocalStorage**.
*   **Tone:** Slovenian "Osebni asistent" tone confirmed for all instructions.
 
### Discussion 4: Auditory Feedback Framework
*   **Context:** Initially "Success Only", but expanded to provide full sensory feedback.
*   **Decision:** Implement sounds for **Success** (Ding), **Error** (Alert), and **Info** (Chime) categories. Pre-load assets in the frontend.
 
### Discussion 5: Theme Readability & Design System
*   **Decision:** Migrate all 12+ core pages to the **Zinc Palette**. Systematically replace hardcoded Tailwind dark classes with semantic variables.
*   **Animation**: Mandated 300ms smooth transitions for all color changes (R-5).

## Phase 4: Risks & Considerations
 
| Risk | Mitigation |
|:---|:---|
| **UUID Enumeration** | Use Cryptographically Secure Pseudo-Random Number Generators (CSPRNG) for UUID v4. |
| **Audio Fatigue** | Keep sounds < 300ms, subtle (Ding/Chime) and prepare for future "Mute" toggle in v0.17. |
| **Checklist Friction** | Ensure the checklist is non-blocking (user can still use the app freely) and disappears on completion. |
 
## Expert Triad Review
 
### 1. Security & i18n
- **Access Control:** Public summaries use a separate read-only Projection to prevent entity leaks.
- **Tone:** Slovenian "Osebni asistent" tone confirmed for all 5 checklist steps.

### 2. Ops Readiness
- **Panic Switch (Audio):** If auditory feedback causes UX friction, a tactical `NEXT_PUBLIC_AUDIO_DISABLE` flag is available in the environment variables to silence the application without code changes.
- **Rollback (Sharing):** Summary sharing is non-destructive. If a leak is detected, the "Reset Link" action immediately invalidates the current UUID, serving as an instant mitigation.
- **Maintenance:** The Job History cleanup (POV-180) prevents disk bloat, ensuring 99.9% ops reliability during long-running background tasks.
