### **Task 1 POV-68: Implement Master Layout and Integrate Pico.css**

**Title:** `feat(ui): implement master layout and integrate Pico.css`

**Description:**
Create a main Qute template (`main.html`) to define a consistent page structure (header, content, footer). Refactor all existing pages to include this layout. Integrate the Pico.css "class-less" framework via CDN to provide an immediate, modern look and feel.

**Acceptance Criteria:**
- A new `templates/main.html` file is created, defining a common page structure with a `<header>`, `<main>`, and `<footer>`.
- The `<head>` section of `main.html` includes a link to the Pico.css stylesheet from a CDN.
- All existing Qute templates (`topics.html`, `briefings-by-topic.html`, `briefing-detail.html`, `topic-form.html`, and `content-source-form.html`) are refactored to use `{#include main.html}`.
- The application has a visually consistent and modern appearance on all pages, leveraging Pico.css default styles.

### **Task 2 POV-69: Refactor to Semantic HTML and Improve Forms**

**Title:** `feat(ui): refactor UI for semantics, usability, and scalable source selection`

**Description:**
Improve the overall user experience through several key enhancements. Refactor existing templates to use semantic HTML5 elements. Replace the non-scalable `ContentSource` dropdown with a dedicated searchable page to improve usability. Enhance forms to provide clearer validation feedback and preserve user input upon submission failure. Add simple JavaScript confirmations for destructive actions to prevent accidental data loss.

**Acceptance Criteria:**
- Existing templates are refactored to replace generic `<div>` elements with semantic tags like `<nav>`, `<main>`, `<section>`, etc., where appropriate.
- Forms for creating/editing topics are improved:
    - Validation error messages are displayed next to the relevant fields.
    - Submitted values are re-populated in the form if validation fails.
- The dropdown for adding an existing `ContentSource` is replaced with a link to a new searchable page.
- A new page (`/ui/topics/{id}/select-source`) is created that allows searching for existing content sources and adding them to the topic.
- A simple, reusable JavaScript function is added to show a `window.confirm()` dialog before any destructive action (e.g., deleting a topic or content source).
- The "Delete" buttons in the UI now trigger this confirmation dialog.

### **Task 3 POV-70: Create Admin Actions Page**

**Title:** `feat(ui): create admin page for system actions`

**Description:**
Create a simple administrative UI page to trigger system-level actions that are currently only available via REST API. This includes manually starting the content source enrichment and the main orchestration process.

**Acceptance Criteria:**
- A new `AdminResource.java` is created to handle UI requests for admin actions.
- A new Qute template `admin.html` is created.
- The `admin.html` page contains two forms:
    1. A form with a button to trigger `ContentSource` enrichment (`POST /ui/admin/enrich-sources`).
    2. A form with optional `startDate` and `endDate` inputs and a button to trigger the `OrchestratorService` (`POST /ui/admin/run-orchestration`).
- After a successful action, the user is redirected back to the admin page with a confirmation "flash message". In case of a backend failure, the user is redirected back with an error flash message.
- The "Run Enrichment" and "Run Orchestration" buttons trigger a `window.confirm()` dialog before submitting the form, consistent with other actions in the UI.
- The `run-orchestration` endpoint validates input dates. In case of validation failure (e.g., future date, `endDate` before `startDate`), it re-renders the admin page with a user-friendly error message.

### **Task 5 POV-72: Verify Responsiveness and Final Review**

**Title:** `test(ui): execute UI test plan and verify responsiveness`

**Description:**
Perform a final, structured review of the entire UI to ensure all new features work together correctly. This involves extending backend integration tests to check HTML responses and executing a manual test plan. This task serves as the final quality gate for the UI.

**Acceptance Criteria:**
- **Backend Integration Tests:** At least one existing `@QuarkusTest` is extended to:
    - Make a `GET` request to a UI endpoint (e.g., `/ui/topics`).
    - Assert that the response is `200 OK` and the content type is `text/html`.
    - Assert that the response body contains an expected HTML element or text (e.g., `<h1>Topics by User</h1>`).
- **Manual Test Plan Execution:** The following test plan is executed successfully on both desktop and a simulated mobile viewport:
    1. **Navigation:**
        -  Navigate to the home page (`/ui`). Verify that the list of topics is displayed.
        -  Click on a topic link. Verify that breadcrumbs are correct (`Home > Topics > Topic Name`) and a list of briefings is shown.
        -  Navigate to the Admin page (`/ui/admin`). Verify that breadcrumbs are correct (`Home > Admin Actions`).
    2. **CRUD Operations (Topics):**
        -  Create a new topic. Verify that a success flash message appears and the new topic is in the list.
        -  Attempt to create a topic with an empty name. Verify that the form reloads and displays a user-friendly validation error message.
        -  Edit the name of the new topic. Verify the success message and the updated name.
        -  Delete the topic. Verify that the JavaScript confirmation dialog appears, and after confirming, the topic is removed from the list with a success message.
    3. **Admin Actions:**
        -  On the Admin page, click "Run Enrichment". Verify a confirmation dialog appears. After confirming, verify a success flash message appears.
        -  On the Admin page, click "Run Orchestration" without dates. Verify a confirmation dialog appears. After confirming, verify a success flash message appears.
        -  On the Admin page, enter a past `startDate` and `endDate`, then click "Run Orchestration". Verify a confirmation dialog appears. After confirming, verify a success flash message appears.
    4. **Form Validation (Admin):**
        - On the Admin page, attempt to run orchestration with a `startDate` in the future. Verify that the page reloads and displays a user-friendly validation error message.
        - On the Admin page, attempt to run orchestration with an invalid date format (e.g., "not-a-date"). Verify that the page reloads and displays a user-friendly validation error message.
        - On the Admin page, enter an `endDate` that is before the `startDate`. Verify that the page reloads and displays a user-friendly validation error message.
    5. **Responsiveness:**
        -  All pages are readable and usable on a mobile viewport.
        -  There are no major visual glitches (e.g., overlapping elements).
    6. **Adding a Content Source via Search:**
        - Navigate to a topic's detail page, click the link to select a source.
        - On the search page, find and select a content source.
        - Verify you are redirected back to the topic page and the new source appears in the list with a success flash message.
    7. **Removing a Content Source:**
        - From a topic's detail page, click the 'Remove' button for a content source.
        - Verify a confirmation dialog appears.
        - After confirming, verify the source is removed from the list and a success flash message is shown.
