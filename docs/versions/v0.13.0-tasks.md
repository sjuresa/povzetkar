## Task Breakdown

### Task 1 [POV-145]: (Completed) (UX) Global Resilience & Polish
- **Title:** `feat(ux): Implement global safety nets and polished loading states`
- **Description:** 
  Establish the "Professional Grade" feel by removing raw loading text and adding resilience against network failures. Use `sonner` for non-intrusive notifications and `axios-retry` for network stability.
- **Acceptance Criteria:**
  - [x] Unified Toast system using Shadcn `sonner` implemented.
  - [x] Global Error Boundary installed, rendering a custom `ErrorPage` (from Backlog).
  - [x] **Axios Retry Strategy**: `axios-retry` configured for 3 retries on transient errors (from Backlog).
  - [x] Skeleton components created for Dashboard widgets and generic tables.
  - [x] **test(e2e)**: Playwright test verifies that a 500 error triggers the Error Boundary.
- **Documentation:**
  - `Context`: Improved UX resilience is key to user trust.
  - `Update`: Document the new Error Boundary and Toast usage in a (new) `frontend/README.md`.

### Task 2 [POV-146]: (Completed) (UX) Platform Foundations (Profile/Theme/i18n)
- **Title:** `feat(platform): Establish Profile, Theme switching and i18n infrastructure`
- **Description:**
  Create the core user space outside the dashboard. This includes the first dynamic user profile and the infrastructure to support multiple languages.
- **Acceptance Criteria:**
  - [x] Profile page (`/me`) implemented, fetching from `UserApiResource`.
  - [x] Theme selection (Light/Dark/System) fully functional with persistence.
  - [x] `i18next` configured with `en.json` and a language switcher shell.
  - [x] **test(unit)**: Verify theme persistence in `localStorage`.
- **Documentation:**
  - `Context`: Foundational features for personalized user experience.
  - `Update`: Update `ARCHITECTURE.md` to mention i18n and Theme strategies.

### Task 3 [POV-147]: (Completed) (FE) Topic CRUD & Prompt Editing
- **Title:** `feat(topic): Full Topic management with Prompt template editing`
- **Description:** 
  Replace existing Topic placeholders with full CRUD functionality using type-safe forms. Enhance the Orval client to handle optimistic locking headers automatically.
- **Acceptance Criteria:**
  - [x] Create/Edit Topic forms implemented with `react-hook-form` + `zod`.
  - [x] **Optimistic Locking**: Orval `customInstance` automatically injects `If-Match` from data version (from Backlog).
  - [x] Prompt template editor (codemirror or simple validated textarea) implemented.
  - [x] **test(e2e)**: Playwright test handles a successful Topic creation flow.
- **Documentation:**
  - `Context`: Topics are the primary organizational unit for users.
  - `Update`: Create `docs/features/topic-management.md`.

### Task 4 [POV-148]: (FE) Source Library & Deep Review
- **Title:** `feat(source): Implement Source Library and Item-level review`

- **Acceptance Criteria:**
  - [ ] Central Source Library (`/sources`) with real-time Shadcn filtering.
  - [ ] **Shared Pagination**: Reusable `Pagination` component extracted from `AuditLog` (from Backlog).
  - [ ] Source Detail page (`/sources/$id`) showing item list and status badges.
  - [ ] **test(integration)**: Verify Filter logic for Source Library in Vitest.
- **Documentation:**
  - `Context`: Users need to verify data ingestion quality.
  - `Update`: Document the Shared Pagination component usage in `frontend/README.md`.
