# Version 0.15.0 Retrospective: Advanced Archive & Operational Excellence

**Status:** Final
**Date:** 2026-03-30

## 1. Overview
This version focuses on delivering "Analytical Depth" to users through a searchable briefing library and robust exporting tools, while maturing the platform's observability baseline.

## 2. Planning Phase Observations
- **User-First Pivot**: Decisions made in Brainstorming to defer Admin User Management in favor of User Export and Library features.
- **Automation Philosophy**: Chose a cross-platform Node.js script for versioning to bridge Windows dev and Linux CI/CD.
- **Monitoring Strategy**: Inclusion of Prometheus/Grafana stack in `docker-compose.yml` to capture both platform and business metrics.

## 3. What Went Well?
- **POV-161**: Backend extension was clean — `FilterBuilder` pattern made adding `search` and `sourceId` filters trivial with no structural changes needed.
- **POV-161**: Existing `SourcesLibraryPage` provided an excellent reference implementation for the new `BriefingLibraryPage`, accelerating frontend development.
- **POV-161**: `react-markdown` was already a dependency, enabling immediate markdown rendering in the Briefing Detail page without new installs.
- **POV-161**: EXISTS subquery for source filtering avoided the cartesian product pitfall documented in lessons-learned, confirming that prior learnings are being applied.
- **POV-162**: Integration of `marked` for HTML export was seamless, providing a more robust alternative to manual string replacement for complex markdown summaries.
- **POV-162**: `react-helmet-async` successfully enabled dynamic SEO metadata without requiring a full SSR architecture, striking a good balance for a specialized SPA.
- **POV-163**: Implemented debounced YouTube channel existence check, which effectively blocks invalid or malformed source additions before they reach the backend — preventing a long-standing source of 404/500 errors.
- **POV-163**: Strict linting rules (no-floating-promises) were successfully applied, uncovering several unhandled async paths in the briefing export flow.
- **POV-163**: The specialized UX/SEO audit scripts significantly improved front-end quality by catching missing accessibility markers (alt text) and heading issues (multiple H1s).
- **POV-164**: Integration of `Micrometer` and `Prometheus` was highly modular. Adding custom metrics to existing services like `OrchestrationManager` was localized and didn't require complex structural changes.
- **POV-164**: Grafana "Dashboards-as-Code" (provisioning) significantly simplified the setup process for the end-user, ensuring a consistent monitoring experience across different local environments.
- **POV-165**: Chunked retention logic worked perfectly in integration tests. Deleting 10 historical records while keeping 5 fresh ones (including the 89-day boundary) proved the reliability of the UTC-based `Instant` logic.
- **POV-165**: Transitioning to Node 24 for the frontend was seamless; no build regressions occurred despite the major version jump, and the updated `@types/node` resolved potential build-time inconsistencies.
- **POV-165**: `QuarkusTransaction.requiringNew()` within the chunked loop provided the necessary isolation for maintenance tasks, ensuring that long-running deletions don't block the entire application.
- **POV-166**: **Domain 0 (GRX)** creation successfully centralized baseline stability tests (Skeletons, Error Boundaries) that were previously fragmented or un-documented.
- **POV-166**: **3-Digit Sequential Indexing** (`TC-DOM-0XX`) significantly improved document scannability and prevents ID collisions as the suite grows.
- **POV-166**: Assigning unique IDs (**US-ING-X**, etc.) to functional requirements established a rock-solid traceability baseline, resolving the "drift" between user stories and tests.
- **POV-167**: The automated planning validator successfully identified **4 critical documentation violations** (broken references and automation gaps) during its first real-world run of the v0.15.0 suite, preventing a non-compliant release.
- **POV-167**: Implemented "Version-Aware Skips" (`until vX.Y.Y`) which transform static bypasses into time-bound deadlines, ensuring that technical debt is automatically surfaced in future cycles.

## 4. What Could Be Improved?
- **POV-161**: The BriefingDetailPage was a placeholder that wasn't identified as in-scope until the user flagged it. Future task definitions should explicitly list all related placeholders that need implementation.
- **POV-161**: Generated API params (`getApiV1BriefingsParams.ts`) had to be manually extended since Orval regeneration requires a full `mvn package` cycle. Consider a faster feedback loop for API type changes.
- **POV-162**: The "Opt-in" sharing model required manual state synchronization in the frontend to avoid a "Copy Link" blink during query refetching. This should be a standardized pattern for all toggle-based actions.
- **POV-163**: Windows/Linux compatibility in `package.json` for `./mvnw` is a persistent friction point in monorepos. Avoid removing `./` solely for local Windows fixes, as it breaks standard Linux/CI environments.
- **POV-163**: E2E Stabilisation — Several Playwright tests had to be removed due to persistent brittleness and instability (flaky locators, state overlaps). Future releases need a more robust strategy for Playwright test maintenance to avoid major cleanups at release time.
- **POV-163**: The `ux_audit.py` script needs more granular tuning for "Hick's Law" to distinguish between navigation menus and data grids.
- **POV-164**: Grafana Mounting — Attempting to mount both a broad folder (`/provisioning`) and a specific sub-folder (`/dashboards`) in the same path space can lead to file-system "shadowing" or overwrites in Docker. Moving all source files to a single `provisioning` hierarchy resolved this.
- **POV-166**: **Manual Re-indexing Friction** — Large-scale re-indexing of test cases (`TC-LIB-01` ➔ `TC-LIB-001`) is error-prone when done manually. Future systemic changes should use a data-driven script to ensure all references (including Section 9 Mapping) are updated atomically.
- **POV-167**: **Static Bypasses** — The initial tool allowed indefinite `validate:skip` overrides. This was identified as a long-term risk and resolved by adding mandatory version-bound expiration logic.

## 5. Technical Observations
- **POV-161**: Database-backed LIKE search is sufficient for current data volumes (~131 briefings). Full-text search (Lucene/pg_trgm) should be reconsidered when the archive exceeds 1,000+ briefings.
- **POV-161**: The `prose-invert` Tailwind typography class provides excellent dark-mode markdown rendering out of the box — no custom CSS needed.
- **POV-162**: For B&W printing, the use of `@media print` with serif fonts (`Times New Roman`) remains the gold standard for professional physical reports, significantly improving the "Premium" feel for clients.
- **POV-165**: PostgreSQL `DELETE` with `LIMIT` is not natively supported in standard JPQL. Using a two-step native ID fetch (`SELECT id ... LIMIT X`) followed by an `IN` clause delete is the most portable and performant way to implement chunking in Hibernate/Panache.
- **POV-166**: **Requirements Traceability** (US ➔ UC ➔ TC) is the most effective guardrail against scope creep. By forcing a link at the planning stage (Step 1.6), we ensure that every line of code has a verified reason for existence.
