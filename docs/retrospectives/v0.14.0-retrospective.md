# Version 0.14.0 Retrospective: Output Mastery & UX Refinement

**Status:** Draft
**Date:** 2026-03-25 (Initialized)

## 1. Overview
This version focuses on transitioning "Professional Grade" features into "User Friendly" tools, refining the orchestration experience, and addressing specific security vulnerabilities.

## 2. Planning Phase Observations
- **Brainstorming Focus**: Prioritized UX fixes (Source intake, Run Now config) over new admin features (User Management) based on user feedback.
- **Methodology Upgrade**: Introduced `use_cases.md` to bridge User Stories and E2E tests.
- **Design Guidance**: Integrated detailed conversion-best-practices for the Landing Page (POV-158).
- **Security Awareness**: Identified specific CVEs (Curl, Busybox) to tackle.

## 3. What Went Well?
- **Stability Fixes**: Successfully identifying and fixing complex transaction isolation issues in integration tests.
- **Backend Modernization**: Migrating to Jakarta CDI without major breaking changes.
- **UX Idempotency**: Implementing 200 fallbacks for existing sources, which significantly improves the Add Source flow.
- **AI Flexibility**: Customizing prompts for topics provides a scalable way to handle multi-language feeds.
- **Trigger Configuration (POV-154)**: Successfully replaced the blind "Play" action with a configurable Trigger Dialog, providing much-needed control over date ranges and dry-runs.
- **Concurrency Debugging (POV-154)**: Identified and resolved a complex `ConcurrentModificationException` in parallel briefing generation by enforcing strict session isolation.
- **Administrative Control (POV-155)**: Implementing manual status overrides and a global content management dashboard significantly improves the maintainability of the ingestion pipeline.
- **DTO Evolution (POV-155)**: Enhancing the `ContentItemDTO` to include source metadata ensures a rich, context-aware administrative UI without extra frontend complexity.
- **Visionary Grounding (POV-158)**: Refined the Landing Page into a premium, distillation-focused entry point. Grounded metadata (Changelog, Roadmap, "Wisdom" tab) in actual project documentation using automated sync scripts, ensuring a factually consistent UX.

## 4. What Could Be Improved?
- **Manual Verification**: We spent a lot of time on Mockito matcher issues; better upfront type safety for service parameters could have mitigated this.
- **Frontend Synchronization**: Lint errors in the frontend (`any` type usage) suggest the need for better domain model synchronization between backend/frontend.
- **Frontend Translations**: Some new feature descriptions were initially missing from the Slovenian locale files.
- **OpenAPI Synchronization (POV-155)**: Discovered that JPA entities shouldn't be used directly in API responses if DTOs are already available. Standardizing on `PaginatedResponse<ContentItemDTO>` resolved 100+ lint errors in the frontend.
- **Scripted Extraction Fragility (POV-158)**: Reliance on regex-based Python scripts for metadata extraction requires strict adherence to Markdown headers. Discovered and fixed a dependency bug in `sync_metadata.py` during deployment.

## 5. Technical Observations
- **MapStruct/Quarkus Integration**: MapStruct mappers must use `componentModel = "jakarta"` instead of `cdi` to avoid `jakarta.enterprise.inject.spi.DeploymentException`.
- **Transaction Visibility**: In tests, `RequiringNew()` transactions commit *immediately*, which can lead to visibility issues in the main test transaction if not properly flushed/cleared.
- **Hibernate Thread Safety (POV-154)**: Passing JPA entities across thread boundaries is highly dangerous. Always pass `Long topicId` and refetch the entity within the worker's transaction to ensure session stability.
- **Timezone Consistency (POV-154)**: `ZoneId.systemDefault()` is an anti-pattern for server environments. Standardizing on `ZoneOffset.UTC` ensured deterministic date-range behavior across local and CI environments.
- **MapStruct Record Support (POV-155)**: MapStruct 1.6 fully supports Java records, simplifying DTO creation while maintaining type safety.
- **Orval/Quarkus Sync (POV-155)**: Frequent backend package runs are required to keep `openapi.json` synchronized when modifying shared DTO schemas.
