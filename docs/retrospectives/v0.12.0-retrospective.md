# Retrospective: v0.12.0 (Frontend MVP & Monorepo Foundations)

**Status:** Draft
**Date:** 2026-03-15

## Preliminary Notes from Planning
*   **Focus:** Establishing a functional, deployable frontend integrated into a modern monorepo structure.
*   **Process:** Continuing the successful "Frontend Spec -> API Contract" workflow from v0.11.
*   **Architecture Goal:** Locking in UI standards early via ADR-004 to prevent fragmented frontend development.
*   **Security:** Extending automated dependency scanning to the frontend layer and integrating OIDC session management into the SPA.

## 1. What Went Well
*   **Architectural Clarity:** Finalizing ADR-0004 before implementation ensures that all frontend decisions are formally documented.
*   **Pragmatism:** Successfully optimized the SEO strategy (Pre-rendering over Vike) and the Monorepo strategy (side-by-side folders over NPM Workspaces) during the planning phase to minimize "overkill" and maintain simple deployment foundations.
*   **Monorepo Migration (POV-135):** The transition was smooth thanks to the early identification of cross-module resource dependencies (Changelog loading). Standardizing on Maven `-pl` flags maintained compatibility with existing CI/CD.
*   **Frontend Scaffolding (POV-136):** Using `@tailwindcss/vite` (Tailwind 4) greatly simplified configuration. Root-level orchestration via `package.json` successfully bridged the gap between NPM and Maven lifecycles.
*   **API Automation (POV-137):** Orval successfully bridged the gap between the Java backend and TypeScript frontend, generating 100% type-safe hooks. This eliminated manual DTO maintenance and reduced integration risk.
*   **Resilient Foundations:** The global response interceptor now robustly handles the backend's custom response envelope and standardizes error propagation, ensuring consistency across all future UI components.
*   **Auth & Shell (POV-138):** Successfully delivered the "First Paint" using Zustand for state and TanStack Router for type-safe guards. The "Midnight Slate" design achieved a premium feel with glassmorphism and smooth sidebar transitions.
*   **Dashboard Experience (POV-139):** The "Getting Started" guide successfully handled the cold-start problem for new users. Using statistical widgets with skeletons provided an immediate premium feel even before data loaded.
*   **Real-time Observability (POV-140):** Successfully bridged the backend's SSE stream to the UI. The introduction of the Zustand `eventStore` enabled reactive UI updates (badges/toasts) without introducing N+1 polling patterns.
*   **Auth Flow Optimization:** Transitioning to a direct `/auth/login` redirect pattern for the SPA significantly reduced user friction and eliminated redundant "Login" button clicks.
*   **Robust Origin Validation:** Implementing `java.net.URI` based normalization resolved brittle CORS matching issues related to default ports (80/443).
*   **Audit Log Observability (POV-142):** Successfully implemented the technical audit log UI. Transitioning `PaginatedResponse` from a record to a class enabled 100% type-safe OpenAPI models for collection items, eliminating `unknown[]` in the frontend and providing a robust pattern for all future paginated resources.

## 2. What Didn't Go Well
*   **Linting Friction:** Transitioning to strict ESLint rules for the frontend required significant refactoring of the initial API client. Specifically, handling `any` types from `JSON.parse` and environment variables required explicit type assertions and `Record<string, string>` casts to satisfy the 2025 standard rules. Standardizing the 150+ errors across the codebase was a significant but necessary time investment to reach a "zero warning" state.
*   **Checklist Sensitivity:** The automated UX audit and SEO checker initial runs flagged many internal build files (`target`, `.quarkus`, `playwright-report`, `backend`). This required refining the ignore patterns in the Python audit scripts to focus only on production-ready source code.
*   **Dev-Stack Instability (POV-138):** Attempting to use Vite 8 (released 3 days ago) caused severe peer dependency conflicts with `@tailwindcss/vite` and `vitest`, leading to `EPERM` errors and installation hangs. Downgrading to Vite 6 was required to restore environment stability.
*   **Vitest Suite Gaps (POV-139):** Component tests were initially ignored by the test runner because the `vite.config.ts` was restricted to the `src/test` folder. Expanding this to the entire `src` directory was necessary to support modern component-co-located testing patterns.
*   **SSE Infinite Loop (POV-140):** An infinite loop was discovered post-implementation. The `useJobEvents` effect re-ran on every state change (including pulses) because it lacked a stable selector for store actions. Additionally, the `DashboardPage` used an unstable filter selector that returned a new array reference on every store update, triggering a "Maximum update depth exceeded" error. This was resolved by implementing `useShallow` and stable action selectors.
*   **OIDC Redirect Loop:** Discovered an infinite redirect loop on the backend root path (`/`) caused by incorrect anonymous access handling in `LoginResource`. Resolved by ensuring root-level anonymous requests trigger the appropriate login flow without recursive redirects.
*   **Production SPA 404s:** Encountered 404 errors for client-side routes (e.g., `/dashboard`) when served from the unified Docker image. Resolved by implementing a robust `SpaRoutingHandler` and enabling `quarkus.http.serve-index-html-for-not-found`.

## 3. What Have We Learned
*   **ViteSSG Beta Compatibility:** Some versions of `vite-react-ssg` may have type mismatches with the latest Vite 6+ or React 19 types. Using `@ts-expect-error` sparingly is necessary for build compliance while the ecosystem matures.
*   **Bleeding Edge Risks:** Being on the absolute latest version of a major build tool (Vite 8) while using beta-grade plugins (Tailwind 4) is a recipe for environment breakage. Prefer the "latest stable" (Vite 6/7) until the ecosystem catches up.
