# Version 0.13.0 Retrospective: Input Mastery & UX Foundation

**Status:** Final
**Date:** 2026-03-19

## 1. Overview
This version focused on transitioning from MVP to "Professional Grade" by mastering system inputs (Topics/Sources) and refining the UI/UX foundation.

## 2. Planning Phase Observations
- **Strategic Pivot:** The decision to pivot from "Production Hardening" to "UX Foundation" was crucial. It highlighted that backend maturity must be matched by frontend professional-grade patterns (Skeletons, Error Boundaries) to ensure user trust.
- **Improved Documentation Standards:** Adopting the narrative "Pros/Cons" format (inspired by v0.4.3) for the planning process proved highly effective for capturing architectural rationale and strategic alignment.
- **Integrated QA vs. Bulk Testing:** Shifting from a large, standalone "Task 7: Automation" to integrated `test` sub-tasks within each feature ensures that quality is built-in from the start, rather than added as an afterthought.
- **Precise Estimation:** Using detailed breakdowns and a 20% contingency provides a more realistic view of the effort required for "Professional Grade" polish.

## 3. What Went Well?
*   **Unified Resilience Pattern:** Combining `axios-retry` at the network level with `ErrorBoundary` + `throwOnError` at the UI level creates a seamless safety net for users. Failure states are now professional-grade "glitch in matrix" views instead of broken components.
*   **Integrated Verification:** Running E2E tests specifically for error states (500 mocks) ensured that the global error boundary is not just installed but functional.
*   **Semantic Theme Foundations:** The decision to use semantic CSS variables in Tailwind 4 allowed for a robust Light/Dark/System theme system that was surprisingly easy to implement across multiple components after the initial tokens were set.
*   **Hybrid i18n Strategy:** Bundling English and lazy-loading Slovenian provided an excellent balance between core performance and localized flexibility.
*   **Job Stacking UX:** Reverting to stacked toast notifications for background jobs provided a much more informative and less aggressive update pattern than replacing a single toast.
*   **Source Transparency (POV-148):** The implementation of the Source Library and Source Detail pages significantly improved system observability. Users can now "drill down" from a high-level briefing to the raw content items (including their **Duration**) and read their official **Summaries** with full markdown support. The addition of a **Reference Tag** (ITEM-ID) adds a "Source of Truth" feel to the data.
*   **Secrets Fail-Fast (POV-149):** Implementing a `StartupEvent`-based config validator provided immediate value. The pattern of using `ConfigProvider.getConfig()` instead of `@ConfigProperty` injection avoids startup crashes when keys are missing, allowing the validator to report *all* missing keys at once.

## 4. What Could Be Improved?
*   **E2E Timeout for Retries:** When testing resilient network layers (`axios-retry`), standard Playwright timeouts (5s) must be increased (15s+) to account for exponential backoff during failures.
*   **Manual UX Audit Nuances:** While automated scripts are good for quick checks, they missed specific modern patterns (e.g. `animate-in fade-in` on page routes or **Tailwind Typography**'s default top margins on the first heading). Manual review was essential for refining fluid typography (`clamp()`), CTA prominence, and ensuring symmetrical padding in the document-style summary modal.
*   **matchMedia Mocking:** JSDOM's lack of `matchMedia` support was an early blocker for component testing that used system theme detection. Centralizing this mock in the test setup is essential for theme-aware SPAs.
*   **Transaction Boundaries in CLI/Jobs:** Background jobs triggered from an executor thread lack a CDI request context, requiring explicit `QuarkusTransaction` management. This should be a Day 0 requirement for all future background tasks.

## 5. Technical Observations
*   **TanStack Query + Global Error Boundaries:** Using `throwOnError: true` in the global `QueryClient` successfully bridges TanStack Query's asynchronous state with React's synchronous `ErrorBoundary` component, simplifying component-level error logic.
*   **Identity API Integration:** The `UserApiResource` provided a clean, unified source for profile data, enabling a rich identity view without redundant frontend state management.
*   **Tailwind Typography vs. Professional Padding:** Standard `.prose` classes include vertical margins that can break symmetrical padding in a modal. Overriding `:first-child { margin-top: 0; }` within `.prose` is necessary to ensure the content aligns perfectly with the container's top boundary.
*   **Duration Formatting Precision:** When displaying content durations, a simple MM:SS format is sufficient for most content, but the helper should be prepared for the HH:MM:SS format to handle longer lectures or live streams gracefully.
*   **Dead Config Discovery (POV-149):** `github.username` and `github.pat` were defined in `application.properties` but never injected in any Java class — pure dead config. A systematic grep for `@ConfigProperty` annotations vs. `application.properties` keys can catch such drift.
*   **Test Profile Namespace (POV-149):** Test overrides `%test.quarkus.youtube.api.key` were using a wrong namespace (`quarkus.youtube.api.key` vs the actual property `youtube.api.key`). This had no visible impact because tests don't call YouTube, but it highlights the importance of verifying that test-profile overrides target the correct property names.
